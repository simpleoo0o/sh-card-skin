# 卡面编辑器设计

日期：2026-09-22
状态：已确认

## 背景与目标

AirCard 会把导入的 Wallet 卡面自动缩放并居中裁切为 1536 × 969 PNG，无法手动调整竖版照片的取景，也不能叠加用于区分卡片的机构 Logo。

本项目提供一个完全运行在浏览器中的静态卡面编辑器。用户可以调整照片取景，在卡面上叠加上海公共交通卡 Logo 或自定义 Logo，并导出可直接交给 AirCard 使用的 1536 × 969 PNG。项目部署在 GitHub Pages，不设置服务端，用户素材不离开浏览器。

## 范围

首版包含：

- 上传 JPG、PNG、WebP 或浏览器能够解码的其他常见照片。
- 拖动、缩放和任意角度旋转照片。
- 提供照片 90° 快速旋转和一键重置。
- 内置上海公共交通卡标准完整 Logo，以及从同一官方素材提取的图形标识版本。
- 上传 PNG、SVG、JPG 或 WebP 自定义 Logo；新 Logo 替换当前 Logo。
- 拖动、缩放和任意角度旋转 Logo。
- 提供 Logo 旋转角度与缩放滑杆，以及一键重置。
- 导出 1536 × 969、sRGB、完整矩形 PNG。
- 支持鼠标、触控板和触屏。
- 使用 Apple 官网式视觉语言和克制、流畅的界面动效。
- 通过 GitHub Actions 自动部署 GitHub Pages。

首版不包含：

- 用户账户、云端存储或素材上传服务。
- 多张 Logo 同时叠加、文字排版、滤镜、历史项目或撤销栈。
- 直接连接 iPhone 或代替 AirCard 写入卡面。
- PWA、离线安装或后端图片转换。

## 技术方案

项目使用 Vite、TypeScript 和 Fabric.js。Fabric.js 负责画布对象、触控手势、选框、缩放点、旋转手柄和 PNG 导出。界面使用原生 HTML 与 CSS，不引入前端框架或额外状态管理库。

逻辑画布始终是 1536 × 969。页面仅按容器宽度缩放它的显示尺寸，因此响应式布局不会改变对象坐标或导出分辨率。

画布只有两个业务图层：

1. 照片图层始终位于底部，并锁定水平/垂直翻转。
2. Logo 图层位于照片之上；选择另一个预设或上传新 Logo 时替换该图层。

Fabric.js 的默认对象控制点承担直接操作。旁边的原生表单控件提供等价的缩放、旋转、快速旋转和重置操作，保证触屏与键盘场景可用。

## 照片裁切约束

照片必须在任何位置、缩放和旋转角度下完全覆盖卡面，不能露出透明或空白区域。

设卡面尺寸为 `Cw × Ch`，原图尺寸为 `Iw × Ih`，照片旋转角为 `θ`。照片居中时允许的最小缩放为：

```text
max(
  (abs(cos θ) * Cw + abs(sin θ) * Ch) / Iw,
  (abs(sin θ) * Cw + abs(cos θ) * Ch) / Ih
)
```

每次缩放或旋转后，编辑器将比例提升到不低于该值。每次拖动后，编辑器把四个卡面角点反向变换到照片局部坐标，并将照片中心夹取到所有角点仍落在照片矩形内的可行区间。这样既允许用户移动取景，也不会在任意角度露白。

“重置照片”恢复为 0°、居中以及刚好覆盖卡面的最小比例。“左转 90°”和“右转 90°”保留当前取景中心，再重新计算最小比例和位置约束。

## Logo 行为与素材

Logo 可以移出卡面一部分，超出画布的区域在导出时自然裁掉；编辑器不允许对象因缩放变成零尺寸或发生翻转。

默认 Logo 尺寸按卡面宽度的约 28% 放置在左下安全区域。重置 Logo 会恢复所选素材的默认尺寸、0° 旋转和该默认位置。

首批内置素材来自上海公共交通卡股份有限公司官网：

- 官方页面：<https://www.sptcc.com/>
- 原始品牌图片：<https://www.sptcc.com/img/logo.png>

仓库保存一份去除均匀底色后的透明版本，并从同一素材生成一个仅含图形标识的透明版本。两者都在素材说明中标注来源与处理方式，不把派生图形标识描述为另一套官方版本。若实施时发现其他可核验的一手官方透明素材，可作为额外预设加入；不能核验来源的图片不内置。

上海公共交通卡名称和标识属于其权利人。本项目只作为非官方个人卡面制作工具，并在 README 中明确无关联声明。

## 页面与操作流程

桌面端使用“控制面板 + 画布”双栏布局；窄屏改为上下布局。页面按以下顺序操作：

1. 用户点击或拖入照片。
2. 编辑器自动修正 EXIF 方向（以浏览器解码结果为准）、居中并铺满卡面。
3. 用户通过点选画布对象或“照片 / Logo”图层按钮选择编辑目标。
4. 用户拖动对象，并使用画布手柄、滑杆或 90° 按钮调整取景。
5. 用户从内置预设选择 Logo，或上传自己的 Logo。
6. 用户点击“导出 PNG”；编辑器取消选框，生成 1536 × 969 PNG，并下载为 `card-skin-YYYYMMDD-HHmmss.png`。

预览容器使用圆角和阴影模拟 Wallet 卡片，但圆角只属于页面外观。实际画布与导出文件保持完整矩形，避免 AirCard 二次裁切后出现透明缺角。

当焦点不在表单控件中时，方向键每次移动当前图层 1 个逻辑像素，按住 Shift 时移动 10 个逻辑像素。所有按钮、滑杆和文件输入都有可见标签、键盘焦点与状态提示。

## 视觉与动效

界面采用 Apple 官网式视觉语言，但不复制 Apple 的页面结构、商标、图片或其他专有素材。设计重点是大字号标题、充足留白、清晰的信息层级、克制的中性色、柔和渐变、精细阴影与半透明材质。

- 字体使用系统字体栈 `-apple-system, BlinkMacSystemFont, "SF Pro Display", "Segoe UI", sans-serif`；不下载或打包 Apple 字体。
- 页面背景使用低对比度径向渐变；编辑控制面板使用带细边框的毛玻璃材质。
- 浅色和深色主题均由 `prefers-color-scheme` 自动适配，所有颜色通过 CSS 自定义属性定义。
- 首屏标题、工具栏和卡面预览依次以淡入、轻微上移和轻微缩放进入，总时长不超过 520ms，缓动使用 `cubic-bezier(0.22, 1, 0.36, 1)`。
- 图层切换、控制面板状态和按钮反馈使用 160–240ms 过渡；上传成功与导出成功使用一次短促的缩放/淡出反馈。
- 用户直接拖动、缩放或旋转画布对象时不添加滞后的补间动画，保证指针与对象同步。
- 页面滚动只用于窄屏布局，不制作长篇产品展示式滚动动画。
- 在 `prefers-reduced-motion: reduce` 下关闭入场、位移、缩放和弹性反馈，仅保留即时状态变化。

动效只增强层级和操作反馈，不能阻塞文件选择、画布编辑或导出。

## 数据与隐私

照片和自定义 Logo 通过浏览器 File API 解码，只保存在当前页面内存中。应用不发送网络请求保存用户素材，不写入 localStorage、IndexedDB 或 Cookie。刷新或关闭页面即清除当前作品。

内置 Logo 和应用代码随 GitHub Pages 静态资源加载。README 和页面均说明“所有编辑均在本地浏览器完成”。

## 错误处理

- 未选择照片时禁用导出，并提示先添加照片。
- 文件无法解码、类型不支持或 SVG 无法载入时，在对应上传区域显示错误，不替换当前有效对象。
- 浏览器因图片尺寸或内存不足无法创建画布时，提示用户换用较小图片。
- 导出失败时恢复选框与编辑状态，并显示可重试的错误消息。
- Fabric 对象加载是异步操作；只有新对象完整加载后才替换旧对象，避免失败后丢失当前编辑结果。

## 测试与验证

自动测试使用 Vitest，至少覆盖：

- 0°、90°、45° 和任意角度下的最小照片缩放计算。
- 横图和竖图的初始铺满比例。
- 照片拖动边界夹取，验证四个卡面角点始终位于照片内。
- 90° 快速旋转后的覆盖约束。
- 导出尺寸、文件名和没有照片时的禁用状态。

发布前还需完成：

- TypeScript 类型检查。
- Vite 生产构建。
- 桌面宽屏与手机窄屏的真实浏览器检查。
- 浅色与深色系统主题的对比度和可读性检查。
- 普通动效与 `prefers-reduced-motion` 模式检查。
- 鼠标与触控方式完成照片、Logo 的拖动、缩放和旋转。
- 上传 JPG 照片、透明 PNG Logo 和 SVG Logo 后成功导出。
- 检查导出 PNG 为 1536 × 969，且不包含编辑选框或圆角缺口。
- 检查 GitHub Pages 站点从仓库子路径加载时资源路径正确。

## 部署

仓库使用 `main` 分支。GitHub Actions 在每次推送后安装锁定依赖、运行测试与构建，并通过官方 Pages Actions 发布 `dist`。Vite 的 `base` 设置为 `/sh-card-skin/`，目标地址为：

<https://simpleoo0o.github.io/sh-card-skin/>

工作流只申请 `contents: read`、`pages: write` 和 `id-token: write` 所需权限。

## 验收标准

满足以下条件即视为首版完成：

1. 用户能从竖版照片中通过拖动、缩放和旋转选择卡面区域，任何操作后均不露白。
2. 用户能选择两种上海公共交通卡预设，或上传自定义 Logo，并拖动、缩放和旋转它。
3. 桌面和手机布局均能完成完整操作。
4. 导出的 PNG 精确为 1536 × 969，可作为 AirCard 卡面输入。
5. 编辑过程不上传或持久化用户素材。
6. 页面在浅色与深色主题下呈现一致的 Apple 官网式视觉语言，并正确尊重减少动态效果设置。
7. `main` 分支通过自动检查后发布到 GitHub Pages。
